# CloudBar — Telegram Mini App для вейп-шопа

Витрина вейп-шопа в формате Telegram Mini App (React) плюс Telegram-бот
(grammy), через который полностью управляется магазин: товары, категории,
заказы, промокоды и точки самовывоза. Отдельной веб-админки в мини-аппе нет
— управление магазином происходит только через бота.

## Стек

- **Клиент**: React 18 + TypeScript + Vite, React Router, Zustand (корзина/избранное/сессия),
  Framer Motion, Telegram WebApp SDK.
- **Сервер**: Node.js + Express + better-sqlite3 (файловая БД, без внешних зависимостей).
- **Бот**: grammy. `/start` открывает мини-апп для покупателей, `/admin`
  открывает панель управления магазином прямо в чате (инлайн-кнопки и
  пошаговые сценарии). Сервер уведомляет админов о каждом новом заказе.

## Структура проекта

```
server/   REST API + Telegram-бот (витрина + админ-панель через бота) + SQLite
client/   React-приложение — только витрина для покупателей
```

## Быстрый старт (локально)

```bash
npm install --workspaces

# сервер
cp server/.env.example server/.env
# впишите BOT_TOKEN и свой Telegram ID в ADMIN_IDS в server/.env
npm run seed --workspace server   # заполнить БД демо-данными
npm run dev:server                # http://localhost:8787

# клиент (в отдельном терминале)
npm run dev:client                # http://localhost:5173

# бот (в отдельном терминале, нужен реальный BOT_TOKEN)
npm run bot --workspace server
```

Для разработки вне Telegram клиент подставляет мок `window.Telegram.WebApp`
(см. `client/src/lib/telegram.ts`) — просто откройте `http://localhost:5173/`.

## Продакшн

1. Разверните `server` (Express-приложение) на любом Node-хостинге, добавьте
   `BOT_TOKEN`, `ADMIN_IDS`, `WEBAPP_URL` в переменные окружения.
2. Соберите клиент: `npm run build --workspace client` → раздайте `client/dist`
   как статику по HTTPS (тот же домен или отдельный, главное — HTTPS).
3. У @BotFather выполните `/setmenubutton` или `/newapp`, укажите URL клиента.
4. Запустите бота: `npm run bot --workspace server` (long polling) или разверните
   как webhook. Бот и API должны быть доступны друг другу по сети —
   по умолчанию бот стучится в API на `http://localhost:<PORT>`, это можно
   переопределить переменной `API_BASE_URL`.

## Основной функционал

**Бот**: при первом `/start` бот запрашивает подтверждение возраста 18+
(кнопки «Мне есть 18 лет» / «Мне нет 18 лет») и только после согласия
показывает кнопку входа в магазин; подтверждение сохраняется в БД, повторно
не спрашивается.

**Витрина (мини-апп)**: возрастной гейт 18+ (на случай прямого перехода по
ссылке, минуя бота), ассортимент с поиском по
названию/вкусу/бренду и фильтрами по категориям, карточка товара с выбором
крепости никотина, явным статусом наличия и вкусом, корзина, оформление
заказа (доставка или самовывоз с выбором точки, оплата картой/наличными,
промокоды), история заказов со статус-трекером, избранное, профиль с
бонусным счётом и колесом фортуны (открывается после 3 заказов — приз:
скидочный промокод или бонусные баллы).

**Управление магазином — только через бота** (доступно `ADMIN_IDS`):
командой `/admin` открывается меню:
- **Товары** — список, карточка товара, скрыть/показать, удалить,
  замена фото прямо файлом в чате.
- **Добавить товар** — пошаговый мастер: фото → название → бренд →
  категория → цена → остаток → вкус → крепость никотина → затяжки →
  описание → подтверждение.
- **Заказы** — список, карточка заказа, смена статуса кнопками.
  При оформлении нового заказа админам сразу приходит уведомление с
  деталями и кнопкой открыть заказ.
- **Категории** — список с количеством товаров, создание, переименование,
  удаление (если в категории нет товаров).
- **Точки самовывоза** — список, добавление (название/адрес/часы работы),
  включение/выключение, удаление. Показываются покупателю при оформлении
  самовывоза.
- **Промокоды** — список с использованием, создание (код/скидка/лимит).
- **Статистика** — выручка, заказы, клиенты, средний чек, низкий остаток.
